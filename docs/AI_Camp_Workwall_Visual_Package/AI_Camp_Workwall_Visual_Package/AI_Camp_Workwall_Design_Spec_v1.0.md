## 0. 文档边界与决策状态

本文是可供设计和开发实施的**视觉方案与建议规范**，不是对 `PRD.md` 的业务需求改写。内容分为：

- **已确认**：AI 创造营面向 7–15 岁；品牌主张“有想法，去创造”；网站主页面包括首页、课程与方案、作品墙；目标为帮助访客理解服务并联系团队；作品墙需要展示作品以及关联的创作与成长信息；视觉方向选择 D。
- **本方案建议**：页面五段结构、作品卡片样式、精选区、详情页编排、动效、尺寸与响应式实现参数。以下数值均为推荐设计 Token，需在实际设计稿中校准。
- **待确认/不承诺首期上线**：作品搜索和排序、热度统计、分类体系、详情独立路由、作品试玩、路演视频、分享/二维码、成长报告、六维量化、联系渠道、内容管理方式。

参考截图只提供内容线索，**不可复制其视觉样式，也不可把参考案例冒充实际已完成的学员作品**。

## 1. 目标、受众与设计主张

### 1.1 页面目标

1. 第一眼感知“孩子能够创作出什么”。
2. 通过具体作品和过程记录理解“作品如何从想法走到成品”。
3. 通过可核实的学习行为理解“创作过程中练习了什么”。
4. 自然引导到“课程与方案”及“联系我们”，形成连续浏览路径。

### 1.2 主要访客

以家长/监护人为主要决策访客进行设计，同时允许孩子和家长共同浏览。视觉语言需要兼具可信赖的专业度与轻松、鲜活的创造力；不采用低幼卡通装饰来代替真实作品内容。

### 1.3 设计概念

**数字创作展览馆 / Digital Creation Gallery**。

核心判断：**页面负责安静，作品负责精彩。** 统一、克制的界面让封面和项目故事占据舞台。作品图片可丰富多彩，但控件和品牌色保持单一语法。

设计关键词：**大图、留白、编辑式排版、轻量探索、完整故事、微交互**。

避免：复杂背景渐变、霓虹描边、粒子装饰、无意义玻璃拟态、重复图标、密集数据仪表盘、模板化“优秀学员”荣誉榜。

## 3. 设计系统与 Token

### 3.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--ww-bg` | `#FFFFFF` | 页面主背景 |
| `--ww-bg-soft` | `#F5F5F7` | 次级整块背景、浅底区 |
| `--ww-ink` | `#1D1D1F` | 标题和正文 |
| `--ww-muted` | `#6E6E73` | 本方案建议的浅底次级文本，注意对比度 |
| `--ww-action` | `#0066CC` | 按钮、文本链接、唯一交互强调色 |
| `--ww-focus` | `#0071E3` | 可见键盘焦点 |
| `--ww-action-on-dark` | `#2997FF` | 深色背景上的链接 |
| `--ww-border` | `#E0E0E0` | 轻量边线 |
| `--ww-divider` | `#F0F0F0` | 次要分隔线 |
| `--ww-dark` | `#272729` | 可选深色转化区/背景 |

原则：不使用第二套 UI 强调色；允许作品封面、视频和实际游戏画面保留多彩内容。深色段落最多用在需要戏剧性对比的完整区块，避免多处穿插造成视觉破碎。

### 3.2 字体与字重

优先使用系统字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。SF 系列在非 Apple 平台并非必然可用，不应依赖未经授权分发的字体文件。

| 元素 | 桌面端推荐 | 移动端推荐 | 权重/行高 |
|---|---:|---:|---|
| Hero 主标题 | 56px | 30–36px | 600 / 1.10–1.18 |
| 大区标题 | 40px | 28–32px | 600 / 1.15–1.20 |
| 详情主标题 | 44–52px | 30–36px | 600 / 1.12 |
| 作品卡片标题 | 21px | 18–20px | 600 / 1.3 |
| 正文/详情文案 | 17px | 16–17px | 400 / ≥1.47 |
| 辅助说明 | 14px | 14px | 400 / 1.5 |
| 小标签/元信息 | 12–14px | 12–14px | 400–600 / 1.4 |

标题可使用轻微负字距，中文不机械应用英文负字距；文本不能为追求视觉而牺牲可读性。全站避免随意混用 500 字重，使用 400/600 为主要梯度。

### 3.3 布局、间距与圆角

- 基础间距单位：`8px`；局部允许 4px 微调。
- 内容最大宽度：`1440px`；正文阅读宽度建议 `760–980px`。
- 页面水平留白：桌面 48–64px，平板 24–32px，手机 20px（极窄手机可降至 16px）。
- 大区块上下间距：桌面 96–128px，平板 72–96px，手机 56–72px。
- 卡片横向间距：桌面 24px，平板 20px，手机 16px。
- 卡片封面圆角：`18px`；搜索/按钮：胶囊状 `999px`；全幅区块不做圆角。
- 避免常规卡片阴影；用图片、留白、对齐和文字层次分组。只有特殊悬浮作品素材可使用非常弱的阴影。

### 3.4 图片与媒体

- 列表封面统一 **4:3** 展示区域（允许保留原图并按关键内容安全裁切）。
- 精选项目推荐 **16:9** 或按素材实际构图调整；不可强裁掉核心游戏 HUD、人物或界面文字。
- 首图必须是真实作品媒体或清楚标注的概念/演示素材；禁用毫无关联的图库照代替项目成果。
- 首屏精选图片优先加载；下方网格懒加载；固定 `aspect-ratio` 避免布局跳动。
- 需要定义图片缺失/加载错误占位，且不得凭空生成“真实学员游戏截图”。

## 4. 页面分区规范

### 4.1 Hero / 品牌引入

**目的**：以一句强记忆点的主张赋予作品展示情绪意义。

- 推荐标题：**“每一个想法，都值得被看见。”**
- 推荐副文案：**“一场属于小小创造者的数字作品展。”**
- 桌面居中排版，标题阅读宽度 900px 左右，保证最多约 2 行；手机标题最多约 3 行。
- 背景纯白，不使用背景粒子/装饰浮球。
- Hero 不放大量按钮；可以用一枚克制的下滑提示引导用户进入精选区（候选）。
- 全站导航沿用主站组件，不为作品墙另造视觉系统。

### 4.2 Featured Creation / 精选项目

**目的**：利用一件有代表性的作品引起兴趣并提供完整故事入口。

- 桌面：**左文右图**，文字约 40%，媒体约 60%；横向对齐，整体呈现展品感。
- 手机：**图片在上，文案在下**；禁止把图缩成难以辨认的小缩略图。
- 内容顺序：栏目眉题 → 项目类别/标识 → 项目名称 → 2–3 行简介 → “查看项目故事”。
- 背景可用 `#F5F5F7` 大面积分区；图片主色尽量来自作品自身。
- 不自动轮播。只有素材数量足够且产品价值明确时，才考虑人工切换精选作品。
- 如果精选案例尚未核实，使用**“示例项目 / 创作过程示例”**清晰标记；不写作“学员佳作”。

### 4.3 All Creations / 全部作品

**目的**：让家长和孩子快速浏览不同类型的创意成果。

- 上方大标题“探索作品”，其下可为搜索、分类、排序工具栏。
- 工具栏仅在对应功能获得确认时呈现；不要做无效的搜索框或不可用筛选。
- 桌面作品列表建议 **3 列**为主。1440px 以下按空间弹性排布；当只有 1–2 件作品时不要强行填满三列。
- 页面可以通过首行精选、局部宽图或章节留白营造“不规则艺术画廊”的韵律，但**基础网格仍对齐**；不要使用随机尺寸导致阅读顺序和图片裁切混乱。
- 手机单列，卡片图像完整、文字保持紧凑。
- 列表分页方式（加载更多或分页）待确认；不建议默认无限滚动。

### 4.4 Creative Journey / 创作过程价值区

**目的**：从“作品很有趣”过渡到“为什么孩子在创作中有所收获”。

推荐文案：**“作品背后，还有成长的故事。”**

建议以一条简明过程线描述：`想法 → 规则 → 原型 → 试玩 → 修改 → 展示`。该路径是展示框架，不宣称所有项目都严格经历相同阶段。

- 桌面：水平分布 5–6 个短步骤，重点展示图片/实物痕迹而非抽象图标。
- 手机：可横向可见滚动的步骤条，或竖向叙事；不得出现横向溢出整个页面。
- 每个阶段有真实记录时才显示真实图片及描述；缺资料时使用通用方法论说明，不虚构课堂经历。
- CTA：**“看看一个项目如何诞生”**，跳转到存在完整记录的项目详情（如有）。

### 4.5 课程与咨询转化区

**目的**：把观看热情自然转为下一步行动，而非突然出现强销售推销。

推荐主标题：**“下一个被实现的想法，可能来自你。”**

- 可采用整块深色 `#272729` 与白字，构建整页唯一的深色视觉收束。
- 主操作优先 **“联系我们”**，与 PRD 确认的转化目标保持一致；“了解课程与方案”可作为次级文字链接。
- 没有明确联系方式或承接流程前，按钮不能伪装成已可用的预约/支付功能。
- 底部衔接统一页脚，保留法律/隐私/联系等已有全站信息。

## 5. 作品卡片组件规范

### 5.1 默认组成

```text
┌───────────────────────────────┐
│                               │
│         4:3 作品封面           │
│                               │
└───────────────────────────────┘
  游戏创作                     [类别]
  动物迷宫大乱斗               [标题]
  从简单规则走向可玩的游戏…     [一句话简介]
  示例项目 / 公开授权称呼       [元信息]
```

信息优先级：**封面 > 标题 > 一句话简介 > 类别/公开元信息**。卡片本体不要被浏览量、日期、复杂奖章和多个 CTA 淹没。

### 5.2 尺寸与行为

- 图片框：`aspect-ratio: 4 / 3`，`border-radius: 18px`，`overflow: hidden`。
- 标题 21px / 600（移动 18–20px）；标题尽量不超过 2 行。
- 摘要最多 2 行，超出省略；缺摘要时不要填假文案。
- 卡片整体是一个可聚焦链接，避免图片、标题和箭头成为多个重复焦点。
- 悬停时封面内部放大至 `1.025`，约 `220–280ms`，缓动 `ease-out`；不要改变卡片布局尺寸。
- 键盘 `:focus-visible` 有 2px 聚焦指示；按钮/链接不只靠颜色区分。
- 点击后进入对应项目详情；如果详情暂不可用，应显示明确不可用状态或不开放此卡片。
- 移动端不依赖 hover 才能看到标题和操作；点击反馈可轻微压缩至 `scale(0.98)`。

### 5.3 信息真实性

作者公开称呼、年龄、发布日期、播放量/浏览量仅在取得数据且获准公开时显示。**没有数据时宁可隐藏，不要使用 `999+`、假分数或虚构的小朋友姓名。**

## 6. 搜索、筛选和排序（候选交互）

PRD 保留了“搜索作品名、小名或姓名”“最新贴上”“最近最热”等参考素材，但**尚未确认是否开发**。本节为若实施时的设计约束：

- 搜索：默认只检索作品名称及公开授权的内容字段。作者真实姓名不应默认成为可搜索目标。
- 搜索框：高度 44–48px，胶囊状，前置搜索图标，保留清空、无结果与输入状态。
- 分类：单选 chips，如全部、游戏、工具、动画等；真实分类从已发布作品中归纳，不写死。
- 排序：首期可仅提供“最新发布”；“最近最热”必须定义时间窗口、计算口径和浏览数据采集方式才能启用。
- 工具栏桌面可一行排列；手机采用搜索独占一行 + 分类横滑 + 排序独立控制。
- 空结果：展示友好说明和“清除筛选”操作，不填假作品。
- URL 查询参数是否同步筛选状态、数据分页策略均由开发需求进一步确认。

## 7. 作品详情页

**建议**以独立、可分享的详情页承载完整项目故事（此为视觉与架构建议，不是 PRD 已确认路由形态）。

### 7.1 内容层级

1. 返回作品墙/面包屑。
2. 项目名称、类别、合法可公开的创作者信息、日期。
3. 大幅作品主视觉或演示视频封面。
4. 简洁项目描述：**做了什么、怎么用、最有趣的地方是什么**。
5. 条件式操作：**体验作品**、**观看路演**（仅当资源可用）。
6. 创作历程：时间线 + 更新/课堂记录 + 阶段图像。
7. 创作亮点：问题 → 行动 → 变化 → 学习价值，并链接证据。
8. 成长与收获：六维中有证据的观察描述。
9. 分享/二维码/成长报告（待确认资源与公开权限）。
10. 相关作品或课程/联系引导。

### 7.2 媒体体验

- 视频封面标明播放操作，不自动有声播放。
- 试玩作品需要明确设备支持、加载状态、失败提示和外部链接风险；移动设备不适配时说明原因。
- 没有视频/试玩内容时，隐藏模块而不是放占位的假播放按钮。

### 7.3 创作时间线

- 把 **项目更新（UPDATE）** 与 **课堂记录（SESSION）** 区分为两个真实数据类型；不能把项目更新数直接写成指导课次数。
- 单条记录至少有：阶段/日期、标题、简短描述；媒体可选。
- 顺序以真实记录为准，绝不固定“10 次创作记录”或“8 次课堂”；PRD 的 8 次为特定服务方案指导次数，不能泛化为作品时间线条数。
- 桌面采用左侧时间轴 + 右侧图文记录；手机采用单列自上而下。

### 7.4 成长与六维表现

PRD 的六维包括：**语言表达、逻辑思维、工程思维、用户思维、数学能力、艺术审美**。

建议首期优先展示：`能力维度 → 具体行为/证据 → 对应作品变化或记录`，以文字、照片、引述和观察事实表达。

仅在拥有评价量表、评分标准、评价人、时间等前提后才考虑分数和雷达图；不能把参考图中的示例分数复用成真实测评结果，不暗示孩子之间排名。

## 8. 响应式规范

### 8.1 核心断点（参考原视觉规范并作作品墙适配）

| 视口宽度 | 列表 | 精选区 | 工具栏 | 页边距 |
|---|---|---|---|---|
| `≥ 1441px` | 内容最大 1440px，3 列为主 | 左文右图 | 同行 | 自动居中 + 内部留白 |
| `1069–1440px` | 3 列 | 左文右图 | 同行 | 48–64px |
| `834–1068px` | 2 列 | 比例压缩 / 必要时堆叠 | 允许换行 | 32px |
| `641–833px` | 2 列（空间不足则 1 列） | 上图下文 | 拆行 | 24–32px |
| `420–640px` | 1 列 | 上图下文 | 纵向排列 | 20px |
| `≤ 419px` | 1 列 | 上图下文 | 搜索占满行、分类横滑 | 16–20px |

断点必须跟随内容宽度实际检查，不能只按设备名称判断。尤其注意 640–833px 之间卡片标题与图片安全区。

### 8.2 移动端具体要求

- Hero 标题自然换行，不允许硬编码换行符导致不同机型排版破裂。
- 作品卡片单列，大图优先，文本在图下方。
- 分类 Chips 可横向滚动，但要有溢出线索并支持触摸。
- 所有触摸目标至少 `44 × 44px`。
- 作品体验和外链操作需明确打开目的地；不要使用移动端无效悬停行为。
- 对详情时间线采用单列，视频和图片不超过容器宽度。

## 9. 微交互与动效

| 场景 | 建议动画 | 约束 |
|---|---|---|
| 卡片悬停 | 图片 `scale(1.025)` / 220–280ms | 不触发布局位移 |
| 卡片按下 | `scale(0.98)` / 120ms | 仅触摸/点击反馈 |
| 按钮按下 | `scale(0.95)` | 继承 Apple 规范的按压语法 |
| 工具栏切换 | 颜色/边线状态 150–200ms | 状态必须明显 |
| 页面内容入场 | 轻微透明度变化（可选） | 不以动画妨碍快速阅读 |
| 媒体加载 | 稳定占位后替换真实媒体 | 避免 CLS 与闪烁 |

系统启用 `prefers-reduced-motion: reduce` 时，应取消非必要缩放和入场动画。所有状态变化必须在无动效时也可理解。

## 10. 状态与异常设计

- **无作品**：不能假造学员成果。可显示“创作展正在筹备中”，同时提供课程入口或已明确标注的示例项目。
- **无筛选结果**：提示没有找到匹配内容，允许清空条件。
- **资源不齐全**：缺少体验、视频或成长报告时隐藏相应入口；若展示则说明状态。
- **图片失败**：使用统一浅灰占位与文本，不显示破损图标。
- **加载中**：保留真实卡片尺寸的 skeleton，避免整页跳动。
- **详情链接失效**：提供返回作品墙的恢复路径。
- **未授权/不可公开**：不在列表、索引、分享卡片或第三方预览中暴露相关作品及身份数据。

## 11. 未成年人作品与内容规范

- 学员作品、图像、姓名/昵称、年龄、视频、语音、学习记录和成长报告，均按照各自的公开许可范围处理。
- **购买课程、签署服务协议，不等于自动授权公开展示。** 需有监护人的适当授权与明确范围。
- 不能把参考图、效果图或 AI 制作的示意图标记成真实学员作品。
- 作者姓名尽量采用取得授权的公开昵称，避免公开不必要的身份信息。
- 成长表现只述有证据支持的事实，不作未经核实的教学成效承诺。

## 14. 交付与验收标准

### 视觉验收

- [ ] 整页以白与浅灰为主，蓝色只承担交互语义。
- [ ] 作品主视觉明显强于 UI 装饰；图片不被强制裁掉关键内容。
- [ ] Hero、精选区、作品网格、过程区、CTA 区层次清晰。
- [ ] 文本对齐、字号梯度、间距和圆角遵循统一 Token。
- [ ] 卡片在桌面不密集、在手机完整可读，无横向溢出。

### 交互与可访问性验收

- [ ] 所有可见交互都有可用目标；不存在空链接、假播放、假搜索。
- [ ] 卡片可键盘聚焦并使用 Enter 打开；焦点明显。
- [ ] 手机交互不依赖 hover；点击区域不小于 44px。
- [ ] 图片有适当替代文本；媒体有可理解的标签与失败状态。
- [ ] 减少动态效果设置生效，布局不因图片加载而明显跳动。
- [ ] 搜索/筛选如上线，具备加载、空结果、清空与错误状态。

### 内容与业务验收

- [ ] “真实学员案例”均已核实来源且可公开。
- [ ] 示例案例明确标注，不误导成实际交付成果。
- [ ] 课堂记录与项目更新按真实类型、数量分别呈现。
- [ ] 成长表现具有对应证据；无依据时不显示虚构分数。
- [ ] 主 CTA 导向实际可用的联系渠道，并具备明确后续处理路径。
- [ ] 敏感身份与未成年人作品展示已取得适当授权。
